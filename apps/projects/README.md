# Projects

## GitHub App connection

Projects connects a Kenoo workspace to GitHub through a GitHub App installation.
It does not use a personal access token or expose any GitHub App credentials to
the browser.

Set these server-only environment variables for the Projects deployment:

```text
GITHUB_APP_SLUG=
GITHUB_APP_ID=
GITHUB_APP_PRIVATE_KEY=
GITHUB_WEBHOOK_SECRET=

# Slack OAuth (server-only)
SLACK_CLIENT_ID=
SLACK_CLIENT_SECRET=
SLACK_SIGNING_SECRET=
# Optional when the deployed Projects URL is not the request origin.
SLACK_REDIRECT_URI=

# Notification outbox worker
PROJECT_NOTIFICATION_WORKER_SECRET=
# Vercel Cron uses CRON_SECRET instead if preferred.
CRON_SECRET=
```

`GITHUB_APP_PRIVATE_KEY` is the private key generated by GitHub for the App.
Store it as a deployment secret; when a deployment provider cannot preserve
multiline values, use literal `\n` line breaks. The public app URL comes from
the existing `NEXT_PUBLIC_PROJECTS_URL` setting.

Configure the GitHub App registration as follows:

- Set the **Setup URL** to `{NEXT_PUBLIC_PROJECTS_URL}/api/oauth/github/callback`.
- Enable **Redirect on update** so Projects can refresh the installation after
  repository access changes.
- Do not enable **Request user authorization (OAuth) during installation** for
  this flow. Installation verification is performed server-side with the GitHub
  App identity.
- Grant the initial read-only repository permissions: Contents, Pull requests,
  Issues, Metadata, and Commit statuses.
- Enable the GitHub App webhook and set its **Webhook URL** to
  `{NEXT_PUBLIC_PROJECTS_URL}/api/webhooks/github`.
- Set the GitHub App **Webhook secret** to the exact server-only
  `GITHUB_WEBHOOK_SECRET` value. The endpoint rejects deliveries that do not
  carry a valid `X-Hub-Signature-256` signature.
- Subscribe to the **Installation**, **Pull request**, **Push**, **Delete**, and
  **Deployment status** events. Pull-request deliveries record merges and can
  complete linked tasks when their configured completion branch is merged into.
  Deployment-status deliveries can complete tasks for repositories configured
  to use a successful deployment environment instead. Delete deliveries
  distinguish a branch removed before merge (disconnect it) from GitHub's
  normal post-merge cleanup (retain it as history). The existing read-only
  **Contents** and **Pull requests** permissions are sufficient for these
  subscriptions.
  `installation_repositories` deliveries are sent to GitHub Apps automatically.
- The endpoint currently handles installation lifecycle events (suspension,
  restoration, and removal) and accepts GitHub's automatic repository-access
  update deliveries. Project, PR, and issue syncing is intentionally separate.

For local development, GitHub must still be able to reach the configured Setup
URL. Use a separate development GitHub App or temporarily configure a public
tunnel URL; a localhost callback cannot be reached by GitHub.

GitHub adds an `installation_id` and returns the state supplied to the
installation URL. Projects validates that state against the signed-in Kenoo
user and workspace, verifies the installation using a short-lived server-only
GitHub App JWT, and stores only installation metadata in the existing
`account_connections` table. Installation access tokens are intentionally not
persisted during setup.

## Slack connection

Projects uses Slack OAuth to connect a Kenoo account to a Slack workspace. Set
the Slack app's OAuth redirect URL to
`{NEXT_PUBLIC_PROJECTS_URL}/api/oauth/slack/callback`, then add the bot scopes
`chat:write`, `channels:read`, and `groups:read`. The Slack client ID, client
secret, and signing secret must remain server-only. The Projects Slack settings
page lets an account choose the public and private channels available to the
installed Slack app.

## Notification outbox worker

Task, assignment, and status changes are captured in Supabase's
`project_notification_outbox` table. Supabase asynchronously invokes
`/api/internal/process-project-notifications` after each outbox insert using
`pg_net`; the worker claims the durable outbox row and processes it.

The worker is protected with:

```text
Authorization: Bearer $PROJECT_NOTIFICATION_WORKER_SECRET
```

The worker owns delivery decisions and reuses the Projects SES email
templates and Slack server helper. It is safe to run multiple workers because
jobs are claimed with `FOR UPDATE SKIP LOCKED`; failed jobs are retried with
backoff. Keep the endpoint private and never expose the worker secret to the
browser. Supabase Vault stores the matching worker secret, so no polling cron
is required.
